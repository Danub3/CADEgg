CADEgg 2026-09-11 答疑复盘与缺陷分析

依据：2026-09-11 答疑截图（26 页）+ 当前工作区代码审查 + 本地构建/测试结果。生成日期：2026-09-11。
一句话结论：CADEgg 的方向有辨识度，已经形成“自然语言 → 场景路由 → 知识卡 → 确定性 CAD 工具 → 校核 → 可追溯记录”的雏形；下一阶段决定作品质量的不是再堆模型，而是把证据链、评测集、风险边界、离线演示和更多完整场景做成可验证的工程闭环。

一、答疑会给出的核心判断

主题老师强调的原则对 CADEgg 的直接含义
数字与结论大模型只负责理解、抽取和解释；工程数字必须由公式、规则引擎、优化器或有限元等确定性模块产生。所有尺寸、数量、评分、工程量都必须能回溯到输入、公式、版本和工具输出，模型不能直接“拍数字”。
可靠生成同一输入应得到同一输出；推荐“模型理解 + 规则裁决 + 人工拍板”三层链路。把模型输出限制为结构化字段和候选方案，最终放行由规则和人工确认完成。
检索与证据“有出处”不等于“可核验”。引用必须来自本次检索，包含规范名、版本/年份、条款、页码或原文；查不到就诚实拒答。知识卡必须带来源状态和原文摘录，检索失败必须进入拒答/转人工分支，不能用记忆补齐。
视觉与评测��线前必须回答类别集合、数据来源、场景覆盖和阈值依据；安全识别优先控制漏报，并分开统计误报。需要真实、对抗、边界样本集；阈值来自验证集曲线，不应写成未经测量的“90%/85%”。
反馈学习用户反馈不能直接训练；应经过人工抽检、离线评测、达标后版本化更新。建立反馈落库 → 抽检标注 → 离线评测 → 版本发布四步数据回流，避免脏数据和分布漂移。
人机边界低风险自动答，中风险给建议，高风险强制转人工；边界必须在代码中有角色、状态和流转。不仅要在提示词里写“人工审核”，还要有风险分级、确认状态、审计记录和不可绕过的权限锁。
演示交付链接失效、断网、环境依赖和未标注 Mock 是常见致命问题；必须准备在线、本地、录屏三级备份。演示包应能断网跑核心链路，所有模拟数据和未实现能力必须在界面与文档中显式标注。

三、作品当前缺陷

1. 证据链还没有闭环（P0）

问题：knowledge.rs 运行时只读取知识卡；search_scenes 以关键词命中数排序。卡片虽然有 citations，但没有把“本次检索命中的原文片段、版本有效期、检索时间、证据是否足够”作为结构化结果参与决策。
  • 风险：同义词、错别字、跨场景描述容易漏检或误命中；查不到时仍可能由模型常识补答。
  • 改法：检索结果增加 source_id/version/excerpt/page/effective_status/retrieved_at/confidence；关键结论没有合格 citation 时强制输出“未找到依据，转人工/官方渠道”。
  • 验收：随机抽查 30 条引用，条款存在率、原文一致率、现行版本率均达到 100%；无依据问题拒答率达到 100%。

2. 评测集和指标仍偏“演示型”（P0）

问题：基准目前每模型 6 个固定小请求，评分器通过是否出现“200”“7000”“5000”等字符串打分；这能测回归，却不能证明工程可靠性。截图要求 30–100 条真实/对抗样本、正常/边界/对抗三类覆盖，并把召回率、精确率、路由准确率分开。
  • 缺少按场景分层的混淆矩阵：漏报和误报没有独立仪表盘。
  • 阈值没有 PR 曲线或验证集依据；“准确率/命中率”不应作为无来源宣传数字。
  • 真实 AutoCAD 烟测和 API 在线测试被标记 ignored，当前基线不能代表现场交付。
  • 改法：建立版本化评测集（建议首批 60 条：6 场景 × 10，含 20% 对抗），记录输入、期望场景、必填字段、期望工具、规则结果和人工标签；每次改动自动跑离线集。

3. 场景覆盖有“注册但不可交付”断层（P0）

场景当前能力缺口建议顺序
洞口盖板/洞口防护已注册关键词和参数无确定性 draw/validate，无专属知识卡兜底。第一批扩展，和现有临边场景形成对抗测试。
楼梯临边/平台防护已注册无出图/校核。第二批，补充线性构件和楼梯几何。
安全通道/防护棚已注册无出图/校核，结构安全边界更复杂。第三批，先知识审查后确定性构件。
脚手架、临电、洞口组合场景主要是知识/追问尚无场景注册或完整工具闭环。作为扩展路线，不应在当前演示中宣称已支持。

4. 人机边界还停留在工具确认层（P1）

  • requires_confirmation 主要针对删除、修改和 run_lisp；安全场景的出图工具目前 requires_approval: false。
  • “高风险只给建议，最终结论人工确认”尚未统一建模为 risk_level → recommendation → human_decision → effective_state。
  • 改法：所有安全场景输出风险等级；高风险禁止直接标记“合格/放行”，必须生成待审核单，记录审核人、时间、依据和修改前后差异。

5. 取消、超时与轮转机制需要现场验证（P1）

  • 代码已加入 90 秒流式静默超时、15 秒建连超时、900 秒单轮上限和取消哨兵，这是正确方向。
  • 但当前没有真实网络抖动、半连接、服务端只发心跳、AutoCAD 工具执行中取消的集成测试；这些正是截图指出的演示致命点。
  • 改法：增加可控 Mock Server 和 Bridge 故障注入，验证停止后不触发 failover、不重复执行工具、已画对象保留。

6. 基准评分与成本指标仍有占位性质（P1）

  • benchmark.rs 的 cost 分数对未知价格使用占位 0.5；这不能用于严肃的模型选择结论。
  • 固定字符串 scorer 容易被模型“说出数字”而非真正调用正确工具绕过。
  • 改法：评分以结构化 tool call、参数 schema、规则校核结果和实际 token/延迟为主；价格按供应商当日公开价版本化记录。

7. 演示与可交付性仍依赖本机环境（P1）

  • AutoCAD、Bridge、API Key、网络和特定版本均是前置条件；10 个真实 AutoCAD 测试被忽略。
  • 目前需要补齐“离线演示包”：本地模型响应回放、Mock Bridge、预生成 DWG/截图、明确的 Mock 水印和三分钟操作脚本。

8. 工程卫生问题（P2）

  • Rust 测试有未使用赋值和死字段 warning，应在提交前清零。
  • 仓库中已有若干本地规划/日志规则，编码显示曾出现乱码；后续文档统一 UTF-8，并避免把私人材料混入仓库。
  • 本次已将 2026_9_11答疑/ 与 2026_9_11未来项目发展总章程/ 加入 .gitignore。

五、答辩时建议的诚实表述

定位：“CADEgg 不是让大模型直接画图或直接判定合格，而是让大模型负责理解意图和抽取字段，再由版本化知识卡、确定性规则和 AutoCAD 工具生成可复核结果；高风险结论保留人工拍板。”
当前边界：“当前已有三个安全场景完成出图、校核和模型空间快照闭环；洞口盖板、楼梯临边、安全通道已完成注册和边界设计，正在补确定性工具。评测和在线可靠性仍在建设，不把演示数据冒充实测结论。”
创新点：“创新不在于接入一个聊天模型，而在于把施工安全图纸任务拆成场景路由、证据链、规则裁决、确定性绘图、人工确认和全过程留痕，形成可审计的工程 Agent。”
