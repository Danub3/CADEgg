# CADEgg 演示讲解要点（2026-08 版）

> 面向近期 2 周内的演示。主线场景：电梯井口防护门（建筑施工安全防护图纸）。
> 演示前检查清单见文末。

---

## 一、一句话定位

**CADEgg：挂在 AutoCAD 上的施工安全防护图纸智能助手** —— 说人话画安全防护图，知识卡可溯源，模型可轮转，全程可审计。

## 二、演示流程（约 5-8 分钟）

### 场景 1：自然语言 → 规范图纸（核心，2 分钟）

1. 在聊天框输入：「画一个电梯井口防护门，洞口宽 1800、高 1500，上翻式」。
2. 观察点（讲给评委听）：
   - 模型先给出**执行计划 + 参数确认**（缺参会追问，而不是直接瞎画）；
   - 点击执行后，AutoCAD 里**实时画出**防护门：门框、上翻式门扇、踢脚板、警示牌、材料表；
   - 图上所有关键尺寸都来自知识卡里的国标底线（踢脚板 200mm 等）。
3. 输入「校核这个防护门」，展示**校核面板**：逐条对照规范输出通过/不通过。

### 场景 2：知识溯源（1 分钟）

- 打开帮助面板 → 模型星级与证据表：星级全部来自 38 模型实测基准（可展示 benchmark-results.md）。
- 知识卡演示：指出图上某个尺寸（如踢脚板 200mm）→ 说明它对应哪条规范原文、哪张知识卡。

### 场景 3：模型轮转与遥测（1 分钟）

- 设置面板里切换 GLM/DeepSeek/千问/Kimi，解释自动轮转（failover）逻辑；
- 显示上一条消息的遥测：模型、首 token 时间、总耗时、token 用量；
- 如现场网络允许：现场跑一次「基准 → 重跑失败模型」展示客观评测。

### 场景 4（可选加时）：编辑工具链（1 分钟）

- 「把这条线镜像到另一侧」→ mirror_handle；
- 「修剪到这条边界」→ trim_by_handle；
- 说明全部走 AutoCAD 内部 .NET bridge（不是外部 COM），稳定且可审计。

## 三、常见追问与回答要点

| 问题 | 回答要点 |
| --- | --- |
| 模型画错了怎么办？ | 每步都有 UNDO 撤回；工具调用可审计；出图前有执行计划确认 |
| 会不会乱画/跑 LISP？ | 比赛模式下 run_lisp 被禁用；工具面白名单化；破坏性操作需人工确认 |
| 模型为什么选这个？ | 38 模型实测基准（意图/JSON/规范问答 6 用例），星级可溯源 |
| 图纸数据安全吗？ | API Key 仅存本机 settings.json；记忆携带需显式开关；对话可本地导出 |

## 四、演示前检查清单

- [ ] CADEgg exe 已重建并启动（含最新星级与模型列表）
- [ ] AutoCAD 已打开且 bridge 已加载（右下角桥接状态显示 Bridge 已连接）
- [ ] 至少一个 provider 的 API Key 已配置（推荐 glm-4.5-flash 作轻量 + glm-5.2 作强模型）
- [ ] 网络可用（智谱/DeepSeek 官方端点直连）
- [ ] 提前跑通一遍电梯井口防护 smoke test（cargo test elevator_shaft_protection_smoke_test_round_trip -- --ignored）
- [ ] 聊天窗口是新建 session（干净历史，避免长上下文干扰）

## 五、已知风险与规避

1. **Kimi k 系列 temperature**：后端已有回退逻辑；现场演示避免切 Kimi 冷门模型。
2. **AutoCAD 卡死**：如果图面不动，等 2-3 秒（bridge 事务提交 + REGEN）；不要连续狂点执行。
3. **免费模型限流**：轻量档位选 glm-4.5-flash（实测稳定 4★）。
